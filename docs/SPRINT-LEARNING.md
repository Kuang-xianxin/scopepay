# 本轮实现与学习：ScopePay 1.2

这次围绕“审批的是哪份采购范围、收款人是谁、响应没回来怎么办”补边界，没有重新堆框架或重复压测。未改产品页面。

## 技术栈怎么分工

- FastAPI 接收操作；Pydantic 严格校验金额、类型和字段。数量与单价使用整数，金额以分计算，避免浮点误差。
- SQLite 用于本轮独立单机验收；原 PostgreSQL/Psycopg 事务、池和跨进程机制保留，未访问共享 PG。新代码没有数据库结构迁移。
- httpx 连接 PayPal Sandbox；MockTransport 只用于协议故障替身。网络替身可以检验“收到错误商户时程序怎么做”，不能证明官方账户能支付。
- 原生 JavaScript 保留现有双语工作台。本轮没有 UI 改动，不声称独立设计审查。
- SHA256 用于报价完整性及发布源文件核验；不是用户身份签名，也不防拥有数据库权限的人重写全部数据和哈希。

## 一个具体例子

采购两张落地页，每张120美元，交接文档60美元，hosting不包含。服务端算出300美元；审批固定报价指纹、金额、币种、审阅人和期限。`PayPal-Request-Id` 是动作的编号，报价指纹是内容的编号，二者不能混用。金额变成301美元的旧确认请求返回409。

原适配只核对订单ID、报价ID和金额；错误商户仍可能被接受。先用故障响应复现失败，再在创建请求中填固定卖家merchant_id，在GET回查中逐项比较。另一个故障是没有capture ID的COMPLETED响应也被当成功；现在这种响应转人工检查，不产生已核验回执。

这不是自动向任意供应商付款：supplier只是采购说明，真实收款人为授权配置的Sandbox卖家。OAuth通过只说明应用凭证被接受，不代表买家授权、商户对应或完整checkout已成功。

## 为什么Unknown不是Failed

发capture前先持久化“已准备派发”。如果处理器已完成而响应丢失，程序不能知道是否扣过。用户刷新页面只能读到Unknown；后端用原订单GET核对，满足同一报价/金额/商户/完成capture身份后保存唯一回执。重复操作返回同一回执。代价是进程恰好在实际发送前退出时也可能保守地保持Unknown，最终需要人工调查；不能为体验好看就重复扣款。

撤销与过期阻止之后的新派发；不能撤回已经发出去的请求。官方幂等键也有保留期限，不能宣称永久exactly-once。

## 配置与验证层次

`Settings.from_env(path)` 只读明确文件，缺文件直接失败，不合并根`.env`或继承provider环境，也不做环境变量插值。启动子进程通过`safe_run.py`保留最小OS环境。预检默认离线；`--oauth`才换token，而且不会创建订单。健康接口区分数据库ready与“凭证已填但平台未探测”。

模型分三层：JSON合法是语法；提取“两个页面”有没有漏数量是语义；是否允许计价和付款是业务授权。前两层通过仍不能给模型资金权限。本轮11436起初无监听，父协调13:46恢复后又复核6例；本项目另在串行锁内补1次真实浏览器→应用→模型，返回two landing pages和handover guide，未把hosting列为交付物。建议仍未勾选、单价0、总额0；收费数量和价格需人设置。没有拿编码agent的回答冒充应用推理，也不把少量合成例当广泛准确率。

## 验证命令与阅读顺序

见[JUDGE-SETUP](JUDGE-SETUP.md)的安装、独立启动、`sandbox_preflight.py`、`judge_scenario.py`和定向pytest命令。修复前两项失败与修复后结果放私有本轮交付目录。旧PG/负载/模型结果不与本轮数量相加。当前实际HTTP测试验证了300美元、撤销、过期、未知恢复、相同回执和导出；首次/重复操作都有业务断言，但没有测本轮性能、冷缓存或新PG容量。

## 面试问题与简短参考答案

1. **为什么金额匹配还不够？** 还要核对收款商户、订单、报价绑定以及真实完成capture；300美元付给错误的人不是成功。
2. **幂等键与数据库唯一约束有什么不同？** 前者约束第三方同一个操作重试，后者约束本地一份报价只存一份回执；需要配合，不能相互替代。
3. **为什么不在事务里等待PayPal？** 网络可能慢或断开，持锁等待会拖住读操作和撤销；先短事务预留，再网络，最后短事务核对令牌并提交。
4. **为什么OAuth预检通过也不能说集成完成？** 它只验证应用身份，买家授权、实际订单、金额/商户和capture都没执行。
5. **怎样证明没有偷偷使用父进程密钥？** 最小子进程环境、显式配置不继承provider变量、配置隔离回归测试，输出只有布尔状态和错误码，不打印密钥。
6. **本轮“73 passed”代表什么？** 指特定源码时点受影响回归通过，主要是本地状态机与HTTP替身；不证明官方Sandbox、真实用户价值、泛化准确率或线上容量。

可用于实习描述的真实说法：“为本地采购审阅原型补充Sandbox商户核验与只认证不交易的预检，复现并修复错误收款人与不完整capture被接受的问题；使用隔离数据验证未知结果恢复与唯一回执。”不要写成已上线生产支付或为真实企业节省资金。
