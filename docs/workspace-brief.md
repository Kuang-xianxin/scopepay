# Workspace surface · Operate

## Direction contract

THESIS: a purchase file with a live action rail. The current task and permitted next action always remain adjacent; the former marketing headline and checkpoint cards are replaced.

OWN-WORLD: white document surfaces, cool slate navigation, deep navy text and a single dark teal action color. Quiet hairline tables, square-ended tab markers, consistent 44px controls, tabular money. System UI typography supports Chinese and English offline.

STORY: locate a purchase, inspect its exact line items and budget, decide once, follow settlement. The primary action changes with persisted state. Unknown settlement becomes a reconcile action, never a green success or red failure.

FIRST VIEWPORT: 208px navigation at left; top bar with mode and language; a large purchase heading and search/filter/list. New purchase opens a two-column editor with source and line items on the left and budget/submit rail on the right. Detail shows a document plus approval/payment rail. Narrow screens collapse navigation and stack the rail after the document.

FORM: code-led purchase register and document review. Seed not run: user explicitly disallowed automatic launcher and delegated design decisions. Seven considered structures: inbox, kanban, spreadsheet, wizard, document review, timeline, split master/detail. Document review + searchable register chosen for immutable financial snapshots and recovery.

FINISH: actual Egolite desktop/narrow bilingual tasks, independent fresh in-thread review under no-subagent instruction, DESIGN.md and token sidecar. No raster assets required.

Search evidence: ui-ux-pro-max queries `procurement approvals financial workspace` and narrower `enterprise procurement dashboard` returned a useful restrained enterprise style but both returned a marketing hero pattern; that pattern is rejected. Operate reference governs task structure. `error summary validation` and `keyboard focus visible` returned directly relevant web UX guidance. Actual stack is vanilla HTML/CSS/JS; no matching exact stack entry, so no invented framework-specific match. No new frontend dependency or CDN.
